# 无头调试与安全回读

本项目历史验证使用过 **DeSmuME 0.9.12/0.9.13 + py-desmume** 的无窗口模式，并用 Python/Unicorn 做少量受控 ARM926 检查。公开仓库不捆绑模拟器、ROM 或用户存档；请自行安装合法来源的软件和自己的 ROM。

## 依赖

```powershell
python -m pip install -r requirements.txt
```

无头运行需要当前环境能导入 `desmume` 和 `Pillow`。Windows 上先确认可视化 DeSmuME 能正常启动，再配置 py-desmume；两个版本的 GUI 与 Python 包并不自动互相提供。

## 运行输入计划

计划是 JSON 数组，支持：

- `{"op":"frames","n":1000}`：冷启动等待；
- `{"op":"key","key":"A","hold":3,"gap":180}`：按键；
- `{"op":"keys","keys":["A","LEFT"],...}`：组合键；
- `{"op":"touch","x":128,"y":96,...}`：触摸；
- `{"op":"shot","name":"title"}`：保存截图；
- `{"op":"ram"}`：导出主 RAM 供研究比较。

示例：

```powershell
python tools/run_headless.py .\input\Slime2_JP.nds `
  --out .\build\headless-title `
  --plan .\examples\title_probe_plan.json
```

运行器会把 ROM SHA 写入 `report.json` 和 `process_exit.json`，默认保存 `checkpoint.dst`。它拒绝使用不同 SHA 的运行目录继续，并且不会向输入 ROM 写回内容。

## 结果解释

无头退出码为 0 只表示这个输入计划在该模拟器构建中完成；它不等于全流程通关、音频正确、真实硬件稳定或所有线路存档兼容。提交截图时请使用原生 1 倍，放大展示不得替代原图。

候选 ROM 交付前先做：

```powershell
python tools/rom_audit.py diff `
  --before .\input\Slime2_JP.nds `
  --after .\build\candidate.nds `
  --allow-file msgdata.bin `
  --allow-file font_data.bin `
  --json-report .\build\candidate-diff.json
```

allowlist 必须与构建脚本声明一致；如果 ARM9、ARM7、overlay、FNT 或未声明 NitroFS 文件发生变化，应停止交付并先解释原因。
